# Maptelo Lite 0.2.0

Nagrywanie programów Java zapisuje każdą czynność także w dużych formularzach zbudowanych jak
Oracle Forms: długich blokach wierszy, polach z przyciskiem „…” i oknach otwieranych przez
formularz.

## Programy Java

- **Wartości wpisane po przewinięciu bloku wierszy nie giną.** Gdy blok pokazuje tylko część
  wierszy, Tab z ostatniego pola ostatniego wiersza przesuwa blok o rekord i program przepisuje
  wszystkie pola naraz. Most Java odczytuje tekst pola dopiero wtedy, gdy dochodzi do zdarzenia,
  więc w takiej serii widział już kolejną pozycję i ilość wpisane przez osobę. Uznawał je za
  zapis programu, a wpisane wartości ginęły. Most podaje teraz, kiedy odczytał tekst, a
  nagrywarka odróżnia przepisanie bloku od pisania. Na programie testowym zbudowanym jak Oracle
  Forms zamówienie z 12 liniami w bloku 8 wierszy zostało zapisane w całości: 61 czynności z 61.
  Wcześniej ginęły wartości linii 9–12.
- **Pola przesunięte przyciskiem „…”.** Przycisk listy wartości, który formularz stawia przy polu
  z kursorem, zmienia położenie pozostałych pól w drzewie okna. Pola są rozpoznawane po miejscu na
  ekranie, więc wartość wpisana przed Tab trafia do właściwego pola.
- **Bez fałszywego Enter po każdym polu.** Pojawienie się albo zniknięcie przycisku „…” tuż po
  pisaniu było brane za reakcję programu na Enter. Teraz odpowiada ono na ruch kursora, nie na
  pisanie.
- **Klawisze odczytywane w osobnym wątku.** Nagrywarka zapisuje też chwilę naciśnięcia klawisza
  piszącego (nigdy to, który to był) oraz Ctrl+L (lista wartości). Dzięki temu odróżnia wartość
  wpisaną przez osobę od wartości, którą formularz wpisał sam po wejściu kursora do pola.
- **Okno nad programem jest odczytywane od razu**, także gdy osoba zamknie je po chwili:
  komunikat po wpisaniu numeru klienta, potwierdzenie po zapisie. Mapa zna wtedy jego treść i z
  niej rozpoznaje przypadki, których nie da się zrobić.
- **Wiersz listy wartości** podany przez program bez położenia nie jest już brany za przycisk „…”
  stojący pod tą samą ścieżką.
- **Połączenie z 32-bitową Javą** uruchamia zawsze tę wersję Maptelo Lite, która je otworzyła, a
  nie inną kopię zainstalowaną w tym samym środowisku Python.

## Mapa

- **Zamknięcie formularza bez zapisu** (Close Form, „Zamknij formularz”) po komunikacie programu
  kończy przypadek, który nie mógł być zrobiony. Mapa pyta wtedy o komunikat, który był
  przyczyną, a nie o pytanie o zapis zmian.
- **Krok zapisu rozpoznany we wszystkich nagraniach.** Nagranie, które wykonało krok w miejscu,
  gdzie inne nagranie zapisuje, też zapisuje, nawet gdy jego ekran nie pokazał jeszcze komunikatu
  o zapisie.
- **Pole wpisywane tylko w części pozycji** (na przykład magazyn) nie rozbija bloku pozycji: krok
  dostaje warunek z kolumny arkusza, która mówi, w których pozycjach ma wartość.
- **Opis wyjątku z komunikatu programu** nie zawiera danych rekordu z pokazu, na przykład nazwy i
  numeru klienta.
- **Krok poza blokiem pozycji, który bierze wartość jednej pozycji**, wykonuje człowiek. Mapa
  opisuje go w uwagach, zamiast przerywać budowę błędem.
- **Wiersz nowego bloku** wskazują wartości wpisane przez sam formularz i puste własne pole, gdy
  rekord go nie wskazuje.
- **Daty liczone od innej daty:** dni robocze i polskie święta (z Wigilią od 2025 roku) są
  rozróżniane od dni kalendarzowych i potwierdzane przez właściciela procesu.
- **Pole pozycji nazwane kodem z rekordu** jest rozpoznawane także wtedy, gdy ekran wymienia
  pozycje również w tabeli.

## Studio i bezpieczeństwo

- Studio wykonuje pracę poza pętlą zdarzeń, zapisuje pliki atomowo, prowadzi rotowany dziennik i
  działa w jednej instancji. Ma osobne ciasteczko dla każdego portu i obsługuje błąd 500 bez
  utraty pracy.
- Arkusz z 2000 wierszami jest wczytywany w 0,5 s (wcześniej 100 s).
- Prywatność: kopia arkusza dla programu Java jest zakryta, a sekrety nie trafiają do zdarzeń
  Studio.

Działania na samym Oracle Forms jeszcze nie potwierdzono. Testy prowadzono na programach Swing
zbudowanych tak jak formularze Oracle Forms.

# Maptelo Lite 0.2.0

Recording Java programs keeps every action, also in large forms built like Oracle Forms: long
blocks of rows, fields with a "…" button, windows the form opens by itself.

## Java programs

- **Values typed after a block of rows moved are no longer lost.** When a block shows only some of
  its rows, Tab from the last field of the last row moves the block by one record and the program
  rewrites every field at once. The Java bridge reads a field's text only when it gets to the
  event, so in such a burst it already saw the next item and quantity the person typed. It took
  them for the program's write, and the typed values were lost. The bridge now says when it read
  the text, and the recorder tells a rewritten block from typing. On a test program built like
  Oracle Forms, an order of 12 lines in a block of 8 rows was recorded in full: 61 actions of 61,
  where the values of lines 9–12 were lost before.
- **Fields moved by the "…" button.** The list-of-values button the form puts next to the field
  with the cursor moves the other fields' places in the window's tree. Fields are known by their
  place on the screen, so a value typed before Tab goes to the right field.
- **No false Enter after every field.** The "…" button coming or going right after the typing was
  taken for the program answering an Enter. It now answers the cursor moving, not the typing.
- **Keys read in a thread of their own.** The recorder also records when a key that writes went
  down (never which one) and Ctrl+L (list of values), so a value the person typed is told from one
  the form wrote itself when the cursor entered the field.
- **A window over the program is read at once**, also when the person closes it a moment later: a
  message after the customer's number, a confirmation after a save. The map knows its words and
  tells from them the cases that cannot be done.
- **A list of values' row** the program tells without a place is no longer taken for the "…"
  button at the same path.
- **The connection to a 32-bit Java** always runs the Maptelo Lite that opened it, not another
  copy installed in the same Python.

## The map

- **Closing a form without saving** (Close Form) after the program's message ends a case that
  could not be done. The map asks about the message that caused it, not about the question to
  save the changes.
- **A saving step is known in every recording.** A recording that did a step where another one
  saves saved too, even when its screen did not show the saved message yet.
- **A field typed in only some of the lines** (such as a warehouse) no longer breaks the block of
  lines: the step gets a condition from the sheet's column that says which lines have a value.
- **An exception's description from the program's message** holds none of the demonstration's
  record values, such as the customer's name and number.
- **A step outside the block of lines that takes one line's value** is done by a person, and the
  map describes it in its notes instead of failing the build.
- **A new block's row** is found by the values the form wrote itself and the row's own empty
  field, when the record does not name it.
- **Dates counted from another date:** working days and Polish public holidays (Christmas Eve from
  2025) are told from calendar days and confirmed by the process owner.
- **An item's field named by the record's code** is recognised also when the screen lists the
  items in a table as well.

## Studio and safety

- Studio works outside its event loop, writes files atomically, keeps a rotated log and runs as
  one instance. It has a cookie per port and handles an error 500 without losing work.
- A sheet of 2000 rows loads in 0.5 s (100 s before).
- Privacy: the sheet's copy for a Java program is masked, and secrets stay out of Studio's
  events.

Oracle Forms itself is not confirmed yet: tests were run on Swing programs built the way Oracle
Forms forms are.
